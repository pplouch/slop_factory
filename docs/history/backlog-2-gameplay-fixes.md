# Feature backlog 2: gameplay fixes

_Historical record for [Rogue idle slop factory survivor rpg ultimate](../../CLAUDE.md) — what landed and why, kept for provenance, not needed for day-to-day work._

## Feature backlog 2 (multi-session)

A second, 11-item feature/bug list, handed over once the first backlog (above) was fully done. Same working conventions as before: one commit per item (or tightly-related pair), headless-verified, real-renderer-screenshot-verified for anything visual/UI, checkboxes/notes updated here as items land. **All 11 items are now done** (see below), deliberately worked in dependency order — quick placement/pathing/economy fixes first, then content (ores/Foundry/Road), with the cost-rebalancing pass saved for last since it needed that new content to exist first to rebalance *against*. If the player hands over a third list, start a fresh section below this one rather than overwriting this history.

**Done:**
- [x] Player should not be able to build in the fog of war — `FogManager.is_revealed(world_pos)` (positions outside the tracked coverage radius count as revealed too, matching the existing "nothing is fogged out there" behavior — see `FogManager`'s own header) is now threaded into `BuildingManager` (`setup()` gained a third `fog: FogManager` param) and checked first in `is_placement_valid`, before any kind-specific rule, so it applies uniformly. Verified via a direct-call debug hook that an explicitly-unrevealed cell blocks placement and the same cell placed right after an explicit reveal doesn't.
- [x] When a conveyor belt has nothing linked to its output, the resources should be stuck, not destroyed — `BeltSegment._try_advance_item` no longer auto-collects to the stockpile when the next cell is empty; it now just returns, leaving `current_item` exactly where it was (at the front edge, `_progress` already at 1.0) so `_process` keeps retrying every frame until something is actually there to take it. `Processor`'s own output auto-collect is untouched — the backlog item named belts specifically, so this is a deliberate scope choice, not an inconsistency by accident (see "Factory automation" above). Verified via a direct-call debug hook that a lone belt's `current_item` survives `_try_advance_item()` unchanged and the wood stockpile doesn't move.
- [x] Resources (buildings) cannot be placed in the water (except Water Extractor, which already requires it) — same `is_placement_valid` pass as the fog check above: every kind except `water_extractor` now rejects a `Biomes.is_water_at` cell. Verified via a direct-call debug hook against an actual sampled water cell: Wall rejected there, Water Extractor accepted there, Wall accepted on ordinary land.
- [x] Have a maximum population stat. Building houses increases it. Player shouldn't be able to hire blobs if max population is reached — see `GameManager` above. `BASE_POPULATION_CAP` (5) comfortably covers the 3 founder blobs plus a couple of early hires before a House is needed; each finished House adds `POPULATION_PER_HOUSE` (5) more. Both `Building.hire_blob` (paid) and its free auto-spawn timer check `can_hire_more()` first — a cap that only blocked paid hires would be trivially bypassable by just waiting for free spawns. `BuildingMenu`'s Hire section and the HUD both show a live "Population: X/Y" readout, polled every frame (not signal-driven, unlike every other stat here) since population changes for reasons no single `GameManager` signal covers -- a blob dying in combat, a House finishing construction. Verified via a direct-call debug hook: starting population 3/5, two hires succeed and a third is correctly rejected at 5/5, building and finishing a House raises the cap to 10 (while still under construction it stays at 5), and hiring becomes possible again immediately after; confirmed the HUD readout visually with a real-renderer screenshot.
- [x] Smooth and improve terrain texture; water ridges should have a border texture to make them more realistic — see `Biomes.water_tint_at`/`Chunk._build_ground_material` above. The ground-texture image doubled to 64×64 with `TEXTURE_NOISE_FREQUENCY` halved alongside it (same mottling pattern size per chunk, resolved at twice the pixel density instead of just denser noise) plus a little fractal detail layered on for a less uniformly speckled look. Verified visually with real-renderer screenshots at both a river and a lake: a clear sandy shoreline ring outside the water line, a lighter shallow band, and a darker deep-water core, replacing the old flat single-color water tint.
- [x] Units cannot walk in deep water, only on borders (to gather water or build Water Extractors) — see `Biomes.is_deep_water_at`/`PathingManager` above. Also tightened Water Extractor's own placement rule to shallow water only (previously any water), since a blob has to be able to walk up to a freshly-placed one to finish building it — deep water being unreachable would otherwise strand it under construction forever. Verified via a direct-call debug hook: sampled ~1000 water cells, confirmed a real mix of deep (372) and shallow (635) among them, confirmed a known deep cell reads solid in the pathing grid and a known shallow one doesn't, confirmed Water Extractor placement rejects the deep cell and accepts the shallow one, and confirmed `compute_path` actually detours (non-empty waypoint list) around a deep-water obstacle instead of cutting straight through it. `Enemy` (no pathing at all, a pre-existing limitation) still walks straight across deep water same as it already does through walls — not a new gap introduced here.
- [x] Resource nodes hold more extractable resources (e.g. a tree ~200 wood, a rock ~1000 stone) — bumped every `ResourceNode` scene's `max_amount` (respawn timing untouched): wood 60→200, stone 40→1000 (the two numbers the backlog named exactly), cactus_fiber/ice_crystal 35→150, obsidian 30→300, mushroom 25→100, food 20→60, water 80→150 (pond) / 200→400 (lake). `Tree` previously had no explicit override at all (relying on `ResourceNode`'s own script defaults, which happened to already read `wood`/60) — gave it an explicit `resource_type`/`max_amount` like every other node scene now has, so a future default-value change elsewhere can't silently retune it. Verified via a direct-call debug hook reading each live node's actual `amount`/`max_amount` in-game.
- [x] Adapt all the different costs so they follow the game's flow (do this last, once the new content below exists) — see "Costs and the economy" above. Concretely: fixed `Foundry` requiring only `town_hall` (the same shallow tier as every basic building) despite being a whole new resource-processing layer, by gating it behind `research_center` instead and raising its `unlock_cost` to match; gave stone an actual purpose it never had (nothing spent it before) by switching `Wall` to cost stone instead of wood, the one clearly-justified case (its own material was already named/colored as stone) rather than touching every building's currency without data to calibrate a bigger change against; documented, rather than silently leaving, the remaining gap (planks still has no sink) and the reasoning for why a hire-cost/unlock-cost mismatch elsewhere (`Builder` cheaper to hire than `Brute` despite unlocking later) is a deliberate reflection of relative stats, not an inconsistency needing a fix. Verified via a direct-call debug hook: placing a Wall spends stone (not wood) and demolishing refunds stone, `Foundry` cannot be unlocked before `research_center` and can immediately afterward; confirmed the corrected cost/currency labels visually in `BuildPalette`.
- [x] This closes out backlog 2 -- all 11 items above are now done.
- [x] Add more resources (Iron, Gold, Silver, Platinum, Slopium), which are ores — see "Ores and the Foundry" above. One ore per biome (5 of 7 biomes), each a plain `ResourceNode` scene reusing the existing harvest/deplete/respawn system unchanged. Slopium is a deliberate joke resource (a glowing goop blob, not a real metal) matching the project's "AI slop" theme. Verified visually with a real-renderer screenshot showing all 5 spawned side by side, distinguishable by color/shape (Slopium's glow especially).
- [x] Ores can be processed into a foundry (new building) — see "Ores and the Foundry" above. One `Foundry` building smelts whichever single ore type is currently buffered into its matching bar, rather than 5 near-identical single-recipe buildings, since nothing asked for a recipe-selection UI. Verified via a direct-call debug hook: buffering stays below the batch threshold until the 3rd ore arrives, a different ore is correctly rejected while one type is locked in, a full batch correctly produces exactly 1 bar and unlocks the buffer afterward (a different ore is then accepted), and the upgrade perk correctly shortens smelt time by the expected 20%; confirmed the building and all 5 ores render correctly with real-renderer screenshots.
- [x] Add a Road `LinkableBuilding` -- roads speed up units walking on them — see `LinkableBuilding`/"Pathfinding integration" above. Same merge-visual shape as Wall/Pipe (a curb edge hides wherever a neighboring Road continues), seeded unlocked from the start like Wall/Belt, and drag-placeable (`BuildingManager.DRAG_PLACE_KINDS`) like the other 3 `LinkableBuilding` kinds. Verified via a direct-call debug hook: `get_speed_multiplier()` reads 1.0 while under construction and 1.5 once finished, the pathing grid never marks a Road cell solid, curbs hide/show correctly between two connected segments, and a Blob's actual computed velocity on a finished Road came out to exactly base-speed × 1.5; confirmed the merged curb/asphalt visual with a real-renderer screenshot.
