# Feature backlog 11: river/lake realism, lava and oil hazard liquids

_Historical record for [Rogue idle slop factory survivor rpg ultimate](../../CLAUDE.md) — what landed and why, kept for provenance, not needed for day-to-day work._

A world-gen ad hoc request: rivers and lakes read as obviously synthetic noise (same repeating meander/blob patterns everywhere), and the map should gain more landscape diversity via lava lakes/rivers and oil lakes, kept coherent with the existing biome system (see `docs/history/backlog-7-worldgen-water-difficulty.md`/`backlog-8-coastlines-and-minigame-vfx.md` for the water system this builds on).

## Making rivers/lakes read as natural

- **Root cause of the "obviously noise" look**: `river_noise`/`lake_noise` were each a single-frequency field sampled directly at world position — a ridged river reads as a perfectly regular sine-wave meander, and a thresholded lake reads as an evenly-spaced, same-size blob lattice, since the underlying field repeats identically everywhere.
- **Fix: domain warp.** `Biomes._warp(world_x, world_z)` offsets the *sampling position* fed into every river/lake (and now lava/oil) noise lookup by a second, independent, much-lower-frequency pair of fields (`warp_x_noise`/`warp_z_noise`, deliberately different frequencies so the warp isn't diagonally symmetric) — the standard technique for breaking a repeating field's regularity without a more exotic noise algorithm, since the warp field itself never repeats in sync with whatever it's warping. Everything *else* (biome classification, ground color, difficulty) stays sampled at the true, unwarped position — only the liquid-feature noise lookups go through `_warp`.
- **River width variation**: `river_width_noise` (a further independent low-frequency field) modulates `RIVER_HALF_WIDTH` per-position (see `_river_half_width_at`, ±45%) so a river visibly narrows and widens along its length instead of holding one constant width forever, matching real rivers. The shore-band width scales proportionally with the local effective half-width so a narrowed stretch doesn't end up with a fixed-width sandy band wider than the river itself.
- **More fractal detail**: `river_noise` bumped from 2 to 4 octaves; `lake_noise` explicitly configured to 4 octaves (rather than relying on FastNoiseLite's own defaults) so a lake's threshold contour picks up real edge irregularity — inlets and points instead of a smooth ellipse.
- **Refactor for reuse, not just water**: the river/lake wetness-curve math (`_tint_for_wetness`/`_river_water_sample`/`_lake_water_sample`) was generalized into two shared, parameterized helpers — `_ridge_liquid_sample` (river-style: inside wherever `|noise| < half_width`) and `_blob_liquid_sample` (lake-style: inside wherever `noise > threshold`) — plus `_tint_for_wetness_colored` taking an explicit shore/shallow/deep color set. Water's own functions became thin wrappers around these with water's own constants; this is what let lava/oil reuse the exact same shape/math without copy-pasting it a third and fourth time (see CLAUDE.md's own "shared helpers vs. inheritance" convention). `_tint_for_wetness` itself was kept as a 1-argument wrapper since an existing regression test calls it directly with a single argument.
- Real water's own public contract (`water_sample_at`/`is_water_at`/`is_deep_water_at`/`water_tint_at`/`shore_factor_at`/`water_depth_factor_at`) is unchanged in shape — only warped/width-varied internally — so every existing regression test pinned to it (the river/lake merge-blend tests, the "depth saturates deep, zero outside water" grid scan, etc.) kept passing unmodified.

## Lava and oil hazard liquids

- **Added `Gate`-style biome coherence for free, not new tuning**: rather than inventing a fresh placement rule, lava (`is_lava_at`) is gated on the *exact* `is_volcanic_at` hotspot field the Volcanic biome branch of `biome_for_world_pos` already uses, and oil (`is_oil_at`) is gated on a factored-out `_is_hot_dry_climate_at` matching the *exact* condition the Desert branch checks. Neither hazard can ever appear anywhere the ground wouldn't independently read as that same biome too — this is what "stay coherent with the biomes" means concretely here, and it required zero new noise-threshold guessing to achieve.
- **Lava**: lake-style pools (`lava_lake_noise`) plus river-style streams (`lava_river_noise`), both merged via a new `_merge_two_liquid_samples` (same wetness-dominance blend water's own river/lake merge uses). Always fully impassable — no shallow wadable tier the way water/oil get, since real lava has no safe edge. Visually: a charred-rock shore ring → molten-orange shallow → near-white-hot deep core, plus a `glow` field (only nonzero past the deep threshold) that `ground.gdshader` adds as emission, reusing the ground texture's existing ember color/pulse for a consistent "glowing volcanic crack" look.
- **Oil**: lake-style pools only (no rivers, per the feature request's own wording), gated on the hot/dry climate condition. Gets the same shallow/deep wading tier real water does (`is_deep_oil_at`), tinted dark soil → near-black slick, no glow.
- **Deliberately a fully separate, parallel system from real water** (`Biomes.hazard_sample_at`), not folded into `water_sample_at`'s own river/lake merge — this was a real design decision, not an oversight: an early draft that broadened `water_sample_at`/`water_depth_factor_at` itself to also reflect lava/oil would have broken an existing regression test asserting "depth is exactly 0 everywhere `is_water_at` is false" (a real, deliberate guard from the river/lake-overlap bugfix in backlog 7/8), since a hot/dry or volcanic point can be simultaneously "not real water" and "hazardous." Keeping hazard sampling as its own function sidesteps that conflict entirely while still rendering correctly: `Chunk._build_ground_material`'s water-mask bake loop computes both samples per pixel and lets a present hazard simply override water's own sample outright (the two are gated to essentially disjoint regions anyway).
- **`is_any_liquid_at`** (water OR lava OR oil) is the new broader "don't place something here" check — `Chunk`'s resource/chest/village/slot-machine scattering, `PropScatter`'s decorative foliage, and `BuildingManager.is_placement_valid`'s general land-only rejection all switched from `is_water_at` to this, so nothing spawns a tree, a chest, or a Town Hall in the middle of a lava lake. `is_water_at` itself is untouched and still used on its own where something specifically means real H2O (Water Extractor's placement gating, which should never work on lava/oil).
- **`PathingManager.setup()`** now also marks `is_lava_at`/`is_deep_oil_at` cells solid in the A*-grid alongside the existing `is_deep_water_at`, so units route around both hazards the same way they already do for deep water.
- **`height_at`** broadened from `is_water_at` to `is_any_liquid_at` so lava/oil also get the same small cosmetic basin dip real water does.
- Verified with `tests/autoload/biomes_test.gd`'s new cases (lava/oil never found inside `PLAINS_RADIUS`, `is_lava_at` always implies `is_volcanic_at`, `is_oil_at`/`is_deep_oil_at` always imply the hot/dry climate gate, `is_any_liquid_at` matches the three-way OR, `hazard_sample_at` is neutral within `PLAINS_RADIUS` and only ever glows where lava is actually present) plus the full existing suite unchanged (147/147), and confirmed visually with real-renderer screenshots: a glowing lava lake/river feeding into a now-organically-meandering river, and a dark, non-circular oil pool on desert sand.

## Follow-up: removed water rivers, made lakes/lava/oil mutually exclusive

A same-day follow-up request: "remove the water rivers, they are not natural enough" plus "lakes and rivers and oil and lava SHOULD NOT overlap... adapt the noise layers so they don't overlap."

- **Real water's river feature is gone.** Even after domain-warping it (see above), a thin winding ridged-noise line never stopped reading as a noise artifact the way a broad lake's threshold blob does once warped/given richer octaves — a fundamentally different problem domain warp doesn't fix for a *line*, only for a *region*. `river_noise`, `river_width_noise`, `RIVER_HALF_WIDTH`/`RIVER_SHORE_BAND`/`DEEP_RIVER_FRACTION`/`RIVER_WIDTH_VARIATION`, `is_river_at`, `_river_half_width_at`, and `_river_water_sample` were all removed outright. Real water is lakes only now: `is_water_at` is a thin wrapper around `is_lake_at`, and `water_sample_at` is a direct pass-through to `_lake_water_sample` (no more river/lake blend — there's only one source left). Lava keeps its own river feature (`lava_river_noise`) unchanged, since the complaint was specifically about *water* rivers reading unnaturally, not lava's.
- **Lakes/lava/oil are now mutually exclusive by construction**, not merely gated to biome-coherent regions that happened to rarely coincide. The map is partitioned into three disjoint zones using the exact conditions the biome classification itself already uses (doubling as the same free biome-coherence trick the original lava/oil design already leaned on): (1) `is_volcanic_at` true → the Lava zone, where only lava can appear; (2) not volcanic but `_is_hot_dry_climate_at` true → the Oil zone, where only oil can appear; (3) neither → the Water zone, where only real water (lakes) can appear. `is_lake_at`/`is_deep_water_at` now explicitly exclude the Lava/Oil zones regardless of what `lake_noise` itself says there, and `is_oil_at`/`is_deep_oil_at` explicitly exclude the Lava zone too (a hot volcanic region is a perfectly plausible climate combination the two underlying noise fields could otherwise both satisfy at once) — giving Lava precedence, matching `hazard_sample_at`'s own pre-existing if/elif ordering. `is_lava_at` itself needed no change; it was already the "top priority" gate.
- `Chunk._build_ground_material`'s hazard-overrides-water bake logic is unchanged in code, but its own reasoning firmed up: since `water_sample_at` now returns neutral everywhere a hazard could possibly be active, the override never actually straddles a real overlap — it's provably disjoint rather than just very unlikely to collide.
- Verified with a new `test_water_lava_and_oil_never_overlap` (a dense grid scan asserting at most one of `is_water_at`/`is_lava_at`/`is_oil_at` is ever true at the same position, and that the scan actually exercises at least one real case of each), the existing river/lake tests updated for the removal (the old river-vs-lake tint-curve test dropped its river half), and the full suite (148/148). Confirmed visually with a real-renderer screenshot: a large, organically-shaped lake with no winding river anywhere in view.

## Follow-up: smoother lava/oil zone transitions

A further same-day follow-up: "Lava and oil are a bit buggy and stop as soon as the biome change. Make transitions smoother."

- **Root cause**: the mutual-exclusivity fix above gated `is_lava_at`/`is_oil_at` on a *hard boolean* (`is_volcanic_at`/`_is_hot_dry_climate_at`) — a field completely independent of the lava/oil feature's own shape noise. Wherever that unrelated boundary happened to cross through the middle of what would otherwise be a bigger lake/river, the feature got clipped there instead of at its own natural edge — a real, visible hard-clip bug, not just a nitpick.
- **Fix: continuous zone strength, not a boolean gate.** `_lava_zone_strength_at`/`_oil_zone_strength_at`/`_water_zone_strength_at` replace the old hard checks with a smoothstep ramp — reusing the *exact* `VOLCANIC_BLEND_BAND`/`BIOME_BLEND_BAND` `blended_ground_color_at` already uses for these same thresholds, so the ground color and the liquid recede in lockstep instead of drifting out of sync. `_ridge_liquid_sample`/`_blob_liquid_sample` both gained a `zone_w` parameter that scales wetness right where it's computed (not as a separate post-hoc pass), and every `is_xxx_at` boolean now checks the *zone-scaled* wetness against `SHORE_WETNESS`/`1.0` instead of a raw noise threshold — so a liquid's whole visible extent shrinks gradually approaching a zone edge, vanishing only right at (or past) the boundary, rather than snapping off at full size.
- **A real consistency bug found and fixed along the way**: `depth` (and `glow`, which mirrors it for lava) was originally computed independently from the raw noise value and *then* scaled by `zone_w`, which could leave a sliver where a scaled-down `depth` was still barely nonzero even though the scaled `wetness` had already dropped below `SHORE_WETNESS` (i.e., a location visually showing a whisper of water/lava tint that gameplay already classified as dry land). Fixed by deriving `depth` directly from the already-scaled `wetness` (`smoothstep(SHORE_WETNESS, 1.0, wetness)`) instead of independently — provably identical to the old formula at full zone strength (worked out algebraically: the old `smoothstep(threshold, threshold+deep_margin, n)` and the new `smoothstep(SHORE_WETNESS, 1.0, wetness)` reduce to the exact same cubic in the shared normalized parameter), but now exact everywhere.
- **A separate, previously-latent tuning bug this pass's own continuity test caught**: `LAVA_SHORE_BAND`/`OIL_SHORE_BAND` were sized in raw noise-unit terms without accounting for lava/oil's noise fields running at a much higher frequency than water's `lake_noise` — the shore transition for a *lake-shaped* feature ended up compressed into roughly one world unit, reading as a sharp edge regardless of the zone-fade fix. Split into `LAVA_LAKE_SHORE_BAND`(0.1)/`LAVA_RIVER_SHORE_BAND`(0.03, kept tighter since a river is a naturally narrow feature and a wide shore band would swamp it entirely) and widened `OIL_SHORE_BAND` (0.025 → 0.08), matching roughly the same world-unit transition width `LAKE_SHORE_BAND` gives real water.
- Real water's own `is_lake_at`/`is_deep_water_at`/`water_sample_at` are unaffected in shape (they already only had one liquid to fade, no dominance precedence to reconsider) — this pass only changed how *strongly gated* they are near the Lava/Oil zones, from a hard 0/1 cut to the same smooth `_water_zone_strength_at` ramp.
- Mutual exclusivity is no longer a mathematically absolute guarantee at every single point (two liquids' independent noise fields could, in a narrow blend band, both coincidentally cross their own threshold at reduced-but-nonzero strength) — a deliberate, accepted trade-off for eliminating the hard-clip bug. Each zone's strength still forces the other two toward exactly zero deep in its own interior, so any residual overlap is confined to a narrow fringe, never either liquid's own core. `test_water_lava_and_oil_never_overlap`'s existing grid scan still passed unchanged after this fix, for whatever that's worth empirically (no violation found at that scan resolution).
- A few existing regression tests had assumptions that legitimately changed and needed updating (not loosened for convenience — each one now asserts the actually-correct property): "`is_lava_at` implies `is_volcanic_at`" became "implies nonzero lava zone strength" (lava now legitimately fades in *before* the hard volcanic threshold); same for oil's hot/dry implication; the deep-oil existence test switched from a blind world-noise grid scan (deep oil got genuinely rarer, needing to sit within the climate's own fully-at-full-strength core, not just its old, looser hard-boolean territory) to a direct formula-level unit test of the shared sampler, plus a new dedicated `test_liquid_sample_wetness_fades_smoothly_with_zone_strength` directly testing the fix itself (monotonic, smooth decay to exactly 0 as zone strength drops, never a sudden jump).
- Verified with the updated/new tests above and the full suite (149/149), plus a real-renderer screenshot at a deliberately-chosen partial-zone-strength point: the ground color, ember speckling, and the lava lake itself all now fade in together gradually with no hard edge anywhere in view.
