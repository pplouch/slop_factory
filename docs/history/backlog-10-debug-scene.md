# Feature backlog 10: a debug scene with a whole pre-built factory town

_Historical record for [Rogue idle slop factory survivor rpg ultimate](../../CLAUDE.md) — what landed and why, kept for provenance, not needed for day-to-day work._

A follow-up request: a new scene, reachable from the Main Menu, for eyeballing/interacting with new building meshes and configurations without waiting on real progression — a flat ground (no `Chunk` streaming), pre-populated with one of every building kind, several conveyor-belt layouts, wall layouts with and without a `Gate`, and a big scattered crowd of blobs, all already fully built the instant the scene loads.

- **`scenes/world/debug_scene.tscn` / `scripts/world/debug_scene.gd`**: mirrors `world.tscn`'s own node structure (same UI panels, `CameraRig`, `WorldEnvironment`/`DirectionalLight3D`) with a new script that reuses the exact same manager split `world.gd` itself does (`PathingManager`/`BuildingManager`/`SelectionManager`/`OrderManager`/`DebugOverlayManager`/`FogManager`/`DayNightManager`, and the same 6-method public facade — `compute_path`/`is_reachable`/`world_to_grid`/`grid_to_world`/`get_structure_at`/`register_structure` — every `BuildableStructure`/`Blob`/`BeltSegment` duck-types against via `get_parent()`) so Build Mode, unit selection/orders, and the debug menu all work exactly as they do in the real game here too. Deliberately **omits** `ChunkManager` and `SpawnManager`'s ambient-enemy population entirely — this scene has no chunks, no biomes, and no enemies by design (see feature request: "no need to create chunks, only a flat surface with buildings on it").
- **One big flat ground plane** (`_build_ground`) replaces `Chunk`'s whole streamed/height-jittered/biome-textured pipeline — a plain plains-green `StandardMaterial3D` on a `PlaneMesh`, with a matching flat `StaticBody3D`/`CollisionShape3D` on the same "Ground" layer (1) every click-to-move/build-mode raycast already expects, so nothing else needed to change to make picking/placement work.
- **`_place_structure(kind_id, cell, facing)`** is a from-scratch helper mirroring `BuildingManager.try_place_structure`'s own real placement sequence (instantiate → set `facing`/`kind_id` → `add_child` → position → `register_structure`/`mark_cell` → `refresh_neighbor_visuals`) minus the cost-spending and auto-assign-builders steps — nothing here should cost resources or need blob labor (see feature request: "all the buildings should be visible on the map as the scene loads"). Every placed structure has `is_under_construction` force-set `false` and `_apply_construction_visual(1.0)` called immediately, so nothing shows the usual "just placed, still rising" stub look.
- **The town itself, in three zones**: one of every real `BuildingKinds` entry (excluding `Wall`/`Gate`/`Belt`/`Road`/`Pipe`, the factory-grid pieces) in a 3x3 grid plus a couple of extra Houses; three distinct belt layouts (a straight 5-segment run, an L-shaped corner turn, and a genuine two-belt merge into one shared output cell — exercising `LinkableBuilding._resolve_fair_input`'s fair-alternation logic, not just laid out to look like a merge); and three wall layouts (a plain run, a run with a `Gate` in the middle, and a small fully-enclosed 3x3 pen whose only entrance is a `Gate` — the last one doubles as a live test case for the "unit surrounded by unbuilt/built walls" pathing fix from the same session, with two blobs pre-placed inside it). 30 blobs (cycling through every `BlobKinds` archetype for variety, ignoring their real tech-tree unlock state — this scene only wants visual variety) are scattered across a wide area.
- **`CameraRig`'s starting position is pinned to the building cluster** rather than left at the world origin (which is empty ground here, since the whole town is laid out to one side) — confirmed via a real-renderer screenshot that the origin's default framing showed nothing useful, fixed by centering on the buildings zone instead so the town is what actually greets the player.
- **Main Menu** gained a "Debug Scene" button (`scripts/ui/main_menu.gd`/`scenes/ui/main_menu.tscn`) alongside Start/Upgrades/Options/Quit, loading `debug_scene.tscn` the same way Start loads `world.tscn`.
- Verified with headless smoke tests (both scenes, plus the Main Menu itself), a real-renderer screenshot confirming the building cluster renders with distinct, non-overlapping meshes and the belts/walls read correctly, and 6 new regression tests (`tests/world/debug_scene_test.gd`) covering population counts, building-kind variety, wall/gate presence, belt-group membership (belts deliberately don't join "buildings", only "structures" — see `BeltSegment`'s own header on why, caught as a test-writing mistake rather than a scene bug), everything already finished construction, and ground-collision coverage for click-to-move. Full gdUnit4 suite (140 cases after this pass) passing throughout.
