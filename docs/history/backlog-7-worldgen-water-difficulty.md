# Feature backlog 7: water cleanup, smooth biomes, distance difficulty, real waves

_Historical record for [Rogue idle slop factory survivor rpg ultimate](../../CLAUDE.md) — what landed and why, kept for provenance, not needed for day-to-day work._

A follow-up ad hoc request: remove the small river-crossing water ponds, smooth the hard biome-color edge at chunk borders, add a distance-based "farther = harder/rarer" difficulty layer, and give standing water real vertex-level waves plus a richer shoreline.

- **Removed river-crossing water ponds**: `water_pond.tscn` (deleted) and its `RIVER_POND_SCENE` spawn branch in `Chunk._maybe_spawn_water` are gone — a river no longer spawns a small harvestable "puddle" at every crossing, since the river itself already reads as water via the ground's own tint/shore-foam shader without one. `Lake` (unchanged) remains the sole harvestable `resource_type = "water"` source. Confirmed via `resource_node.gd`/`OrderManager.ITEM_REQUIRED_FOR_RESOURCE` (keyed by resource type string, not scene) and `WaterExtractor` (placement-gated by `Biomes.is_water_at` terrain classification, not by any resource-node scene existing) that nothing else assumed `water_pond.tscn` specifically existed.
- **Smooth biome-color blending**: `Biomes.blended_ground_color_at` (new) gives the ground's *visual* color a continuous, softened version of `biome_for_world_pos`'s exact same classification tree (temperature/humidity climate grid, volcanic hotspot, `PLAINS_RADIUS` circle), all via `smoothstep`-widened thresholds rather than hard cuts — see its own `_climate_blend_color` helper for the climate-grid math. Deliberately does **not** touch resource/enemy/prop scattering, which still use the coarse single-biome-per-chunk classification (`biome_for_world_pos`, unchanged) — blending *which* resources spawn continuously would have been a much bigger change than the actual complaint (a purely visual one: ground color snapping at a chunk's hard edge). Read per-*vertex* by `Chunk._build_ground_mesh` rather than baked into the chunk's own procedural texture, since a texture tiles *within* one chunk (repeated via `uv_scale`) and so can never carry a whole-chunk-spanning gradient the way vertex colors (which agree exactly with a neighboring chunk's own mesh at their shared border, since both sample the same continuous function) can. `Chunk._build_ground_material`'s texture switched from `biome.ground_color`-tinted to a neutral gray (`TEXTURE_NEUTRAL_BASE`) mottling pattern — the actual hue now comes entirely from the vertex-color multiply in `ground.gdshader`, the same way a real terrain shader separates a grayscale detail texture from a vertex-painted base color. Verified with a real-renderer screenshot at a known swamp→tundra transition (found by scanning `biome_for_world_pos` outward from the origin): a genuinely smooth gradient, no visible chunk-border snap.
- **Difficulty-by-distance noise layer** (see feature request: "the farther the biome is, the rarer the resources and the harder the enemies"): `Biomes.difficulty_at` blends raw distance from the origin (70% weight) with a new broad, slow-varying `difficulty_noise` field (30% weight) so the increase isn't a perfectly circular ring (which would read as artificial, the same reasoning already applied to biome-color blending) while still correlating strongly with "farther = harder". Saturates at `DIFFICULTY_MAX_DISTANCE` (1500). Two derived multipliers: `enemy_difficulty_multiplier_at` (1.0 → `MAX_ENEMY_DIFFICULTY_MULT` 2.5) and `resource_abundance_multiplier_at` (1.0 → `MIN_RESOURCE_ABUNDANCE_MULT` 0.35). `Chunk._scatter_resources` scales both its `RESOURCE_ATTEMPT_CHANCE` and cluster-count roll by the resource multiplier at the chunk's own position. `Enemy` gained a new `@export var difficulty_multiplier` (default 1.0, stacked multiplicatively with `GameManager`'s existing time-based ramp) — set by the *spawner*, not read from `global_position` inside `Enemy._ready()`, because every real spawn call site (`SpawnManager.spawn_one_enemy`/`spawn_enemies_near_base`, `DayNightManager._spawn_wave`) sets `global_position` *after* `add_child()`, and `_ready()` runs synchronously during `add_child()` — reading position there would always sample distance 0 from the origin. All three call sites now compute the spawn position into a local variable first, so `difficulty_multiplier` can be set (matching the "set properties before add_child" convention) before the enemy ever enters the tree.
- **Real water waves + richer shoreline** (see feature request: "water still looks a bit off... a shader on the surface to create waves, and improve the shoreline appearance"): `water_surface.gdshader` (used by `Lake`, the sole surviving standing-water resource node) now displaces vertices with two overlapping sine waves computed in *world* space and converted back to the mesh's own local space via `inverse(MODEL_MATRIX)` — necessary so `wave_amplitude` means the same physical wave height regardless of a given water body's own non-uniform scale (Lake squashes a unit sphere to 0.08 in Y), rather than reading as invisible or absurdly large depending on which mesh it's applied to. The wave height also feeds a cheap brightness cue (a crest catches slightly more light than a trough) and a fresnel-based rim brighten was added using Godot's own already-correctly-transformed `NORMAL`/`VIEW`, on top of the existing animated ripple/sparkle color. `ground.gdshader`'s shoreline foam gained a third, higher-frequency wave layer specifically to break up what would otherwise be an obviously-periodic 2-wave interference pattern, plus a brighter/higher-contrast foam mix.
- Added test coverage for every new `Biomes` function (`blended_ground_color_at`'s bounds/continuity/near-origin-matches-plains, `difficulty_at`'s bounds/distance-saturation, both multipliers' formula-consistency and documented-extreme bounds) and for `Enemy.difficulty_multiplier` actually producing tougher stats — hit and fixed three of my own flawed test assumptions in the process (assuming the independent noise term would stay small near a boundary/extreme when it isn't bounded that tightly by construction; fixed by asserting the real guaranteed bounds and the formula's own internal consistency instead of a guessed numeric window).
- Verified end to end: headless import/smoke checks clean, the full gdUnit4 suite (101 test cases after this pass) all passing, and real-renderer screenshots confirming the smooth biome gradient and the lake's sparkle/fresnel rendering without corruption (a static screenshot can't show wave *motion* itself, but the headless smoke test already confirmed no runtime shader errors from the vertex displacement).

**Known, deliberately out of scope**: chunk unloading. `ChunkManager` remains strictly load-only (`loaded_chunks` only ever grows, confirmed by re-reading the file this pass) — not changed here, since real unload/reload would need a way to persist a chunk's mutated state (resource-node depletion amounts, opened chests, raided villages) across an unload/reload cycle, or accept silently regenerating fresh state and losing player progress in that area, a real risk not attempted without explicit sign-off on that tradeoff.
