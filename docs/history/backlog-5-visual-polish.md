# Feature backlog 5: visual polish pass (post-backlog-4)

_Historical record for [Rogue idle slop factory survivor rpg ultimate](../../CLAUDE.md) — what landed and why, kept for provenance, not needed for day-to-day work._

## Visual polish pass (post-backlog-4)

A one-off ad hoc ask ("improve the textures and add props to make the world more living, give the water's rim a nice effect, add VFX wherever needed"), not part of a numbered backlog -- logged here anyway since it touches the same terrain/chunk code the backlogs above already document.

- **Ground texture**: `Chunk._build_ground_material` gained a second, much-higher-frequency `detail_noise` layer (`DETAIL_SPECKLE_THRESHOLD`/`DETAIL_SPECKLE_DARKEN`) that sparsely darkens scattered pixels on top of the existing mottling -- reads as small dirt-clump/grain flecks breaking up what was a fairly uniform band pattern, the same "layer a finer pass on top" idea the base mottling's own fractal octaves already use, just at a scale those don't reach.
- **Shoreline foam**: `Chunk`'s ground material is now a `ShaderMaterial` (`scripts/world/ground.gdshader`) instead of a plain `StandardMaterial3D` -- the only behavioral difference from the material it replaces is an animated foam/shimmer band right at the water's edge, driven by a new `Biomes.shore_factor_at` (0..1, peaking exactly at the same river/lake noise threshold `water_tint_at` already blends across, reusing its existing shore-band constants rather than new tuning) baked into ground-mesh vertex-color *alpha* by `Chunk._build_ground_mesh` -- the RGB channels still carry the existing land/shore/shallow/deep tint unchanged. `WaterPond`/`Lake`'s own surface material became a second small shader (`scripts/world_objects/water_surface.gdshader`, animated ripple/sparkle) for the same "animate what used to be a flat tint" reason, applied to standing water bodies rather than the ground plane's shoreline.
- **Living-world props**: new `scripts/core/prop_scatter.gd` (`PropScatter`, stateless helper) builds two `MultiMeshInstance3D` layers per chunk -- a foliage layer (small 3-blade tuft clusters, code-generated via `SurfaceTool`, reused for every biome's grass/fern/reed/frost-tuft/ash-scrub look, distinguished only by height/width/color) and a sparser "accent" layer (a tiny stemmed bloom/ember/crystal stud) -- both purely decorative (no collision, no group membership, never referenced again), batched via MultiMesh specifically because a chunk wants 50-90 individual blades and that's wasteful as separate scene instances the way a real harvestable `ResourceNode` needs to be. The foliage material (`scripts/core/grass.gdshader`) adds a gentle wind sway keyed off each blade's own local vertex height (tip bends, base stays planted) with no extra per-vertex data needed beyond what the mesh already has.
- **Ambient particles**: new `scripts/core/ambient_particles.gd` (`AmbientParticles`, stateless helper) adds one small `GPUParticles3D` per chunk -- fireflies for forest/swamp, pollen for plains/jungle, dust haze for desert/volcanic, drifting snow for tundra -- kept deliberately small (`AMOUNT` 10 per chunk) since `ChunkManager.CHUNK_LOAD_RADIUS` can have ~49 chunks loaded at once.
- Verified via headless smoke test (`--quit-after`, both before and after removing a temporary debug hook) with zero runtime errors/warnings beyond the usual force-quit RID/ObjectDB shutdown noise, then confirmed visually with real-renderer screenshots (ground detail speckle, grass tufts, and the redesigned rock/water-pond meshes all render correctly together) -- the day/night cycle happened to start at midnight, so the first screenshot attempt was confirmed via a temporary debug-forced noon before removal, per this file's own "test hooks get removed before finishing" convention.

**Follow-up pass** (same ad hoc request, continued after the player reported the game started at night and asked for more shaders/lighting/beauty):

- **Day/night start bug**: `DayNightManager._elapsed_seconds` started at `0.0`, which `time_of_day_fraction()`'s own doc comment already identified as midnight -- so every fresh session opened already in the darkest part of the cycle, reading as "it's day 1 but looks like night" rather than a working cycle. Fixed by seeding `_elapsed_seconds` to `DAY_LENGTH_SECONDS * START_TIME_FRACTION` (0.5, noon) in `setup()`, plus calling `_apply_lighting()` once immediately there so the very first rendered frame already reflects it instead of waiting a frame for `process()`.
- **Environment overhaul**: world.tscn's `Environment` sub-resource had shipped at pure engine defaults (no glow, no ambient occlusion, default ambient handling) since it was first created -- `World._configure_environment()` (called once from `_ready()`) now enables Glow (tuned so only genuinely emissive materials bloom -- `glow_hdr_threshold` deliberately high enough that ordinary sunlit albedo colors never trigger it) and SSAO for contact shadowing, and gives ambient light its own explicit energy. An ACES tonemap + exposure lift was tried first and reverted after a real-renderer screenshot showed it washing the whole scene into a flat pale look -- documented in `_configure_environment`'s own comment so a future pass doesn't reintroduce the same regression blind.
- **Daytime brightness**: `DayNightManager.DAY_LIGHT_ENERGY` raised modestly (1.0 -> 1.15) and the day sky-top/horizon colors nudged brighter -- kept deliberately small after the Environment overexposure lesson above, verified against a real-renderer screenshot rather than assumed.
- **GemSparkle** (`scripts/core/gem_sparkle.gd` + `.gdshader`): a stateless helper that finds every `MeshInstance3D` whose material is a `StandardMaterial3D` with `emission_enabled` set -- already the existing "this bit glows" marker on every ore nugget/vein/shard/facet, ice crystal, obsidian ember, and Slopium's own body -- and swaps it for a shared animated `ShaderMaterial` (traveling view-angle glint + slow emissive pulse) carrying the original albedo/emission/metallic/roughness forward as uniforms. Called from `ResourceNode._ready()` (covers every ore/crystal scene with zero per-scene changes) and `SlotMachine._ready()` (its glowing screen). Uses `set_surface_override_material` rather than mutating the shared Mesh resource's own `.material`, since multiple sibling meshes (and every other instance of the same ore across the map) can share that same underlying resource.
- **Volcanic ember glow**: `Chunk._build_ground_material`'s texture gained an alpha channel (RGB8 -> RGBA8) that doubles as an "ember mask" -- the same per-pixel `detail_noise` samples that already darken scattered dirt-speckle pixels also mark themselves as embers when the biome is volcanic (0 everywhere on every other biome's texture, a visual no-op there). `ground.gdshader` reads that mask to pulse a glowing crack color into both `ALBEDO` and `EMISSION`. Verified with a direct-call debug hook (`Chunk.generate()` against a manually-built volcanic biome) confirming a real chunk's texture actually contains ember-marked pixels (33/4096) before removing the hook.
- **More lighting**: small `OmniLight3D`s added directly to `chest.tscn` (a soft gold glint), `friendly_village.tscn` (warm hearth glow), `enemy_village.tscn` (ominous red glow near its banner), and `slot_machine.tscn` (warm glow matching its screen's own color) -- all rare-enough-per-chunk world objects that a handful of real-time lights is cheap. Confirmed visually: the slot machine's light pools warm color onto the grass around it exactly as intended.
- Verified end to end with a clean headless smoke test (zero errors/warnings beyond the standard force-quit shutdown noise) and multiple real-renderer screenshots across the tuning iterations -- the first environment-tuning attempt was visibly overexposed and caught specifically because a screenshot was taken and inspected rather than assumed correct from the code alone.
