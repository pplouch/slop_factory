# Feature backlog 9: chunk unloading, real assets, AI/pathfinding fixes, Gate

_Historical record for [Rogue idle slop factory survivor rpg ultimate](../../CLAUDE.md) — what landed and why, kept for provenance, not needed for day-to-day work._

A large ad hoc request: make `ChunkManager` actually reclaim memory by unloading distant chunks (previously deliberately load-only, see backlog 7's own "known, deliberately out of scope" note), start using the newly-added `assets/` folder (a large Kenney-style mesh/UI asset pack) instead of only code-built primitives, fix two specific AI/pathfinding "units get stuck" complaints, and add a Gate building.

## Chunk unloading

- **`ChunkManager` now unloads, not just loads**: `_unload_far_chunks` (called from `process()` right after `ensure_chunks_loaded`) frees any loaded chunk beyond `CHUNK_UNLOAD_RADIUS` (6 chunks — deliberately wider than `CHUNK_LOAD_RADIUS`'s 3, so a camera hovering near the boundary doesn't thrash a chunk in and out of existence every `CHUNK_CHECK_INTERVAL`). This was flagged as a real, measured problem, not a hypothetical one — CLAUDE.md's own stress-test note already recorded ~10.6k nodes across 225 force-loaded chunks costing meaningful framerate on its own, and that number only ever grew under the old load-only design as more of the map got explored.
- **Two things are deliberately never unloaded**, both established as genuinely unsafe to tear down and regenerate after investigating every place in the codebase that references chunk-spawned content (a dedicated research pass covering `Blob`'s states, `OrderManager`/`TaskLock`, `BuildingManager`'s structure registry, every UI panel, and all group-based lookups — summarized below):
  - **A chunk with `Chunk.has_village` true.** `FriendlyVillage`'s trade `offers` are explicitly promised (in its own pre-existing header comment) to "stay fixed... rather than it re-rolling out from under" the player; `EnemyVillage` runs its own live `_looted`/`_respawn_elapsed` raid-cooldown simulation and parents its guard `Enemy` instances *under the same chunk* (unlike `SpawnManager`'s ambient enemies, which are parented under World) — neither is designed to survive being torn down and rebuilt from scratch, and villages are rare (`Chunk.VILLAGE_CHANCE`) enough that excluding their handful of chunks forever costs negligible memory against the whole map.
  - **A chunk any blob is currently standing in, or still travelling toward** (`ChunkManager._is_safe_to_unload`, checking every blob's `global_position` and, if `current_state.is_travelling()`, its `final_target`) — freeing a resource node a blob is mid-harvest on, or walking toward, out from under it would leave that blob holding a dangling reference. The research pass found every actual cross-frame node reference in the codebase (`Blob.pending_harvest_node`/`pending_build_target`, `Extractor.linked_node`, all four UI panels' `_tracked_*` fields, `EnemyVillage._guards`) already wrapped in `is_instance_valid()` at its use sites — strong evidence the codebase was already written defensively against a target disappearing (originally for depletion/demolition/death), which generalizes to chunk unload for free *provided* it happens somewhere neither state is actively watching, which is exactly what this check guards.
  - A chunk skipped either way isn't queued or retried specially — `_unload_far_chunks` just runs again next `CHUNK_CHECK_INTERVAL`, so it becomes eligible on its own once a blob wanders away or finishes travelling.
- **Made chunk generation fully deterministic** so a reload can reproduce exactly what a returning player left behind, since this project has no on-disk save format for world state at all: `Chunk._rng` (a `RandomNumberGenerator` seeded from `hash(chunk_coord)` at the top of `generate()`) now drives every content-placement roll (resource clusters, animal huddle, chest/village/slot-machine spawn + position/rotation/scale) instead of the global `randf()`/`randi_range()` — the same `coord` always produces the identical sequence of objects regardless of how many times it's been generated before. Purely decorative content with nothing to lose (`PropScatter` foliage, `AmbientParticles`) was deliberately left on the global RNG — reseeding those too would just be extra plumbing for a difference no player could actually notice.
- **`Chunk.snapshot_state()`/`generate()`'s new `saved_state` param** close the gap a deterministic reroll can't recover on its own: each tracked resource node's (`_resource_nodes`, populated in creation order by `_scatter_resources`/the animal huddle loop) current harvested `amount`, and whether this coord's `Chest` (if any) was already looted. `ResourceNode.restore_state(saved_amount)` re-applies a saved amount right after a reload's fresh `_ready()` already reset it to full, and for an already-depleted node, resumes the despawn/respawn cycle (skipping the shrink tween — nothing to visually shrink, this node never existed until this exact frame — but still restarting a full `respawn_time` countdown rather than tracking exact remaining time, a deliberate, safe-direction inaccuracy: never better for the player than just staying would have been, for what should be a rare edge case). A looted chest is suppressed *before* `_maybe_spawn_chest` ever instantiates one, not spawned then immediately freed. `ChunkManager._chunk_deltas` (keyed by coord, never cleared) holds these snapshots for the rest of the session, so a coord can be unloaded and reloaded any number of times.
- Verified end to end via a debug hook exercising the full cycle live (deplete a resource node → move the focus far away → confirm the chunk actually unloads and a delta gets recorded → move back → confirm the *same coordinate* reloads as a *new* Chunk instance with the *same* depleted amount), plus confirming a village-containing chunk survives being sent arbitrarily far away, and that a blob mid-command-move toward a distant chunk correctly vetoes unloading it. Added `tests/world/managers/chunk_manager_test.gd` (5 cases) covering the same scenarios as real regression tests, on top of the full existing suite passing unchanged.
